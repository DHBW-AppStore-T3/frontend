Pro Team ein eigener Wert
Sie geben unten eine Eingabe pro Team ein. Beim Deploy bekommt jedes Team genau seinen eigenen Wert.

Warum so

  1. Eine Datei, viele Empfänger. Der häufigste Fall ist ein ZIP für alle. Er braucht einen Ablagepunkt statt einem je Person. „Pro Person unterschiedlich“ ist die bewusste Ausnahme.
  2. Die Leiste zeigt, wer die Datei bekommt. Gefüllter Punkt, Datei da. Leerer Ring, keine Datei. Beim Ablegen füllen sich die Punkte nacheinander: der einzige Moment mit Bewegung.
  3. Geprüft wird beim Ablegen, nicht erst beim Deployen. Endung, Dateigröße und Gesamtgröße: Das Backend lehnt sonst erst beim Deployen ab. Eine Größengrenze je Datei zeigt die Oberfläche nicht an; sie meldet sich nur, wenn eine Datei zu groß ist, und nennt dann keine Zahl.
  4. Namen statt Technik. „Starter-Projekt“ statt starter, kein „STRING“-Schild an einer Datei, Personen statt „Team #1“.
  5. Rot für Bedienung und Zustand, Rot-Dunkel für Fehler und Text auf Rosé. Der Fehler nutzt das Danger-Token, damit er sich vom Marken-Rot der Bedienung unterscheidet.
