# Internationalisierung (i18n)

Wie neue Texte hinzugefügt werden, wie sichere HTML-Interpolation funktioniert und was der Sie-Form-Test prüft.

---

## Setup

Die App nutzt `react-i18next` mit einer einzigen gemeinsamen i18n-Instanz (`src/i18n/index.ts`). Diese Instanz wird sowohl von React-Komponenten (via `useTranslation`) als auch von Nicht-React-Code (z. B. den Router-Guards) genutzt.

**Interpolationsformat:** `{name}` (geschweifte Klammern, wie in vue-i18n — kein `{{name}}`).

**Sprachen:** `de` (Standard, Fallback `en`). Die Auswahl wird in `localStorage` unter dem Schlüssel `locale` gespeichert (`src/i18n/locale.ts`); ist Speicher gesperrt (z. B. in einem eingebetteten Moodle-iframe), gilt die Auswahl nur für die laufende Sitzung. Umgeschaltet wird über `LanguageSwitch` (`src/components/ui/`).

**Rollenbezeichnungen** (`roleLabels.*`) liefert `src/i18n/role-labels.ts`; Texte für Rollen nie fest eintragen.

---

## Texte hinzufügen

Alle deutschen Texte stehen in `src/i18n/locales/de.ts`, englische in `en.ts`. Die Struktur ist ein verschachteltes TypeScript-Objekt — kein JSON.

```ts
// de.ts
MeineView: {
  title: 'Meine Seite',
  save: 'Speichern',
  hint: 'Bitte geben Sie einen Namen ein.',
}
```

In der Komponente:

```tsx
const { t } = useTranslation()
t('MeineView.title')           // → 'Meine Seite'
t('MeineView.hint')            // → 'Bitte geben Sie einen Namen ein.'
```

Mit Interpolation:

```ts
// de.ts
greeting: 'Hallo {name}',
```

```tsx
t('MeineView.greeting', { name: 'Anna' })   // → 'Hallo Anna'
```

Mehrzahl über i18next-Suffixe `_one` / `_other` und den Parameter `{count}`:

```ts
// de.ts
deploymentStudentCount_one: '{count} Student',
deploymentStudentCount_other: '{count} Studenten',
```

```tsx
t('DeploymentDetailView.deploymentStudentCount', { count: n })
```

> Beide Sprachdateien müssen immer synchron gehalten werden. Ein Schlüssel nur in `de.ts` erscheint in der englischen UI als roher Schlüsseltext; ein Schlüssel nur in `en.ts` erscheint in der deutschen UI auf Englisch (Fallback `en`).

## Sie-Form-Test

`tests/unit/i18n/sie-form.spec.ts` stellt sicher, dass `de.ts` durchgehend die formelle Anrede (Sie) verwendet. Der Test schlägt fehl bei:

- Du-Pronomen (`du`, `dich`, `dir`, `dein`, …)
- Du-Imperativen zu Beginn eines Textes oder nach „Bitte" (`Wähle`, `Lade`, `Klicke`, …)

**Erlaubte Ausnahmen:**
- Statusmeldungen in Ellipsen-Form (`STATUS_ELLIPSIS`: beginnt mit Lade, Speichere, Lösche, Entferne, Warte oder Suche und endet auf `...` oder `…`), z. B. `Lade Kurs...`
- Die beiden Fortschritts-Toasts `Setze Deployment (fort) — siehe Live-Fortschritt unten.` und `Lösche Deployment — siehe Live-Fortschritt unten.` (explizit ausgenommen via `STATUS_TOASTS`-Regex im Test)

Wenn ein neuer Imperativ hinzugefügt wird, der im Test noch nicht bekannt ist, muss er in die `IMPERATIVES`-Liste in der Testdatei eingetragen werden.

## `BoldSlot` — ein Wert fett darstellen

Wenn ein Nutzerwert (App-Name, Kursname, Workload-Name) in einem Satz fett erscheinen soll, kommt `BoldSlot` zum Einsatz (`src/i18n/BoldSlot.tsx`). Der Wert wird als Text-Kind gerendert — er kann kein Markup injizieren.

```ts
// de.ts
confirmDeleteMessage: 'Das Deployment {name} löschen?',
```

```tsx
<BoldSlot
  i18nKey="DeploymentDetailView.confirmDeleteMessage"
  slot="name"
  value={deployment.name}
/>
// → 'Das Deployment <strong>Mein Deployment</strong> löschen?'
```

Optionale Props:
- `mono` — gibt den Wert in `font-mono` aus (für technische Bezeichner wie Workload-Namen)
- `params` — weitere Interpolationsparameter neben dem einen fett dargestellten Slot

> Für mehr als einen hervorgehobenen Wert oder für komplexere Strukturen: `translateHtml` verwenden (siehe unten).

## `translateHtml` — Markup in Übersetzungen

Wenn eine Übersetzung echtes HTML enthält (z. B. `<a href="…">` oder `<strong>` um mehrere Stellen), wird `translateHtml` aus `src/i18n/html.ts` verwendet.

```ts
// de.ts
inviteText: 'Fügen Sie <strong>{user}</strong> als Collaborator hinzu.',
```

```tsx
import { translateHtml } from '@/i18n/html'

<span
  dangerouslySetInnerHTML={{
    __html: translateHtml('AppsCreateView.info.inviteText', { user: app.githubUser }, t),
  }}
/>
```

**Sicherheit:** `translateHtml` HTML-escaped alle übergebenen String-Parameter automatisch (`&`, `<`, `>`, `"`, `'`); Zahlen und andere Typen bleiben unverändert. Die i18next-Option `escapeValue` ist ausgeschaltet, weil React Text selbst escaped. Nutzerkontrollierte Werte können so kein Markup injizieren. Das Markup im Übersetzungsstring selbst ist vertrauenswürdig (liegt im Code, nicht vom Nutzer).

**Wann `translateHtml` statt `t()`:**

| Situation | Lösung |
|---|---|
| Reiner Text, ein Wert fett | `BoldSlot` |
| Text mit `<a>`, `<strong>` um mehrere Werte | `translateHtml` + `dangerouslySetInnerHTML` |
| Reiner Text ohne Hervorhebung | `t()` |

> `translateHtml` nie ohne `dangerouslySetInnerHTML` einsetzen — der Rückgabewert ist ein HTML-String, kein React-Element.

## Außerhalb von React

Für Code, der keinen `useTranslation`-Hook aufrufen kann (Router-Guards, Stores), steht die geteilte Instanz direkt zur Verfügung:

```ts
import i18n from '@/i18n'

i18n.t('router.forbidden', { roles: 'Admin' })   // z. B. in src/router/guards.ts
```
