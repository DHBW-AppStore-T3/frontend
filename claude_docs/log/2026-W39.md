### 2026-09-24 — LTI 1.3 launch + self-service-ui handoff identity (frontend#9)

Extended `useKeycloak.ts` with `handoffToken` alongside the existing
`ltiToken`/`devEmail`, plus `setHandoffUser()` mirroring `setLtiUser()`.
`getAccessToken()`/`ensureValidToken()` now check ltiToken → handoffToken →
devEmail → Keycloak session, in that order. `auth.store.ts` gained
`setLtiUser`/`setHandoffUser` (and a minimal `setDevUser`, needed for
`main.ts`'s existing dev-only `?sso_handoff=` branch to type-check —
not itself in scope of #9, but required by the pre-existing pattern
`main.ts` already used). Both new actions build an immediate stub `User`
and replace it via a backgrounded (non-awaited) `fetchMe()`, keeping the
stub on failure rather than bouncing to an unauthenticated state.

`main.ts` now wraps boot in an async IIFE (was: fire-and-forget
`auth.initialize()` after `app.mount()`) dispatching on
`?lti=1&session_token=...`, `?handoff=1&handoff_token=...`, or
(dev-only) `?sso_handoff=`, cleaning up all consumed query params via
`history.replaceState` before mounting. `auth.service.ts` gained
`safeGet`/`safeSet`/`safeRemove` localStorage wrappers (SecurityError
in a Moodle iframe must not abort boot); `axios.ts`/`AppLayout.vue`/
`i18n/index.ts` got the same try/catch treatment on their remaining
direct `localStorage` calls.

Backend contract consumed: `POST /lti13/launch` → `?lti=1&...&session_token=`
and `POST /handoff/mint` → `{email, handoff_token}` fed into self-service-ui's
redirect (backend#9, merged into backend's `dev` earlier today).

Full suite green (117 tests, incl. 17 new), `vue-tsc -b && vite build`
clean. No coverage gate applies to PRs targeting `dev` (only `main`,
verified against `.github/workflows/*.yml` directly rather than
trusting HANDOVER.md's summary — backend's equivalent PR failed exactly
this way on an assumption that didn't hold).
